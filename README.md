# 银行审计 · 函证与多线任务协同平台

> Bank Audit Confirmation & Engagement Hub — 面向中国银行业审计场景的轻量协同平台。
> 把审计现场最耗人的两件事——**函证（询证函）全流程跟踪**与**多个被审计单位/科目的并行任务管理**——做成一个可视化、可留痕、可导出的工具。

一条命令启动，浏览器打开即用。技术栈 **FastAPI + DuckDB + 原生前端**，复用了对账/账龄的数据引擎思路（源自个人项目 logistics-settlement-recon）。

## ✨ 核心功能

| 模块 | 说明 | 审计价值 |
|---|---|---|
| **函证看板** | 5 状态看板：待发函 → 已发出 → 已回函 → 差异待跟进 → 已核销；拖拽/按钮双流程，且**状态机校验非法跳转**（不能跳过发函/回函直接核销） | 一眼看清每封函卡在哪，且流程不可被绕过 |
| **回函差异自动比对** | 录入回函金额，自动与账面余额勾稽生成差异，非零差异自动进入「差异待跟进」 | 把"对账"能力嵌入函证，替代手工核对 |
| **差异归因（三分法）** | 差异卡片强制归因：未达账项 / 记账错误 / 舞弊迹象 / 待核实 | 落实"回函差异 ≠ 错报"的职业判断 |
| **函证覆盖率监控** | 总览按科目实时算金额覆盖率；**银行存款不足 100% 即红色预警** | 从"任务工具"升格为"审计质量控制工具" |
| **未回函催办 / 替代程序** | 发函超 30 天未回自动标记催函；提示银行存款**不可用替代程序替代** | 补上函证闭环最易漏的一环 |
| **询证函生成** | 从台账一键生成**银行询证函 / 企业往来询证函**（积极式/消极式，风险驱动）；**一封银行函聚合该行全部存款+借款事项**；往来函含"非催款结算依据"条款；可打印 PDF、下载 Word | 覆盖发函前制单，且符合《银行函证操作指引》格式 |
| **多线任务跟踪** | 同时跟踪多个「单位 × 科目」项目四阶段（计划/现场/复核/报告），自动标记逾期与函证完成度 | 项目组协同、进度一屏掌握 |
| **账龄分析** | **仅往来款**（应收/应付/其他应收）按入账日分桶，1 年以上红标 | 辅助确定函证/抽凭重点 |
| **台账导入 & 审计留痕** | 支持 Excel 台账导入；发函/回函/催函/归因/状态流转全部写入 events 表 | 可追溯，符合底稿留痕要求 |

## 🧱 架构

```
浏览器 (单页前端: 原生 JS + Tailwind)
        │  fetch  /api/*
        ▼
FastAPI (app.py)  ──  letter.py  询证函 HTML / Word 生成
        │
        ▼
DuckDB (db.py)   engagements · ledger · confirmations · events
```

- **db.py** — 建表、演示种子数据、加锁的查询助手、账龄/进度聚合。
- **letter.py** — 依科目分流生成银行/往来询证函（HTML 可打印 + python-docx 导出）。
- **app.py** — REST API：看板状态流转、回函差异计算、批量生成、Excel 导入、阶段推进。
- **static/index.html** — 四个视图：总览 / 函证看板 / 多线任务 / 台账与生成。

数据表关系：`engagements 1—n ledger 1—1 confirmations`，`confirmations 1—n events`。

## 📇 数据模型要点

- **confirmations.status** 状态机：`待发函 → 已发出 →（录入回函）→ 已回函 | 差异待跟进 →（核销）→ 已核销`；
  服务端 `STATUS_TRANSITIONS` 白名单校验，拒绝跳跃迁移，且进入"已回函/差异待跟进"必须带回函金额。
- **difference = book_amount − reply_amount**，非 0 即自动落入「差异待跟进」并要求归因。
- **资产负债表日**动态取上一个已结束年度 12-31；函证发/回函日锚定其后约 35/50 天（次年 2 月），避免时间线穿帮。
- **账龄** 仅对往来款项计算 = `date_diff('day', entry_date, 资产负债表日)`。
- **逾期** = `due_date < 今天 且 阶段 ≠ 报告`。
- **函证方式**风险驱动：小额（<50 万）同质往来款用消极式，银行存款/借款/大额/关联方用积极式（准则 1312）。

> **术语说明**：本平台流程末态用「**已核销**」，沿用银行**内部审计**的"问题整改—销号/核销"口径。
> 若用于**注册会计师函证**语境，等义术语应为「**已结项 / 已核对相符**」——两者仅命名差异，流程一致。

## 🏦 业务背景与准则依据

**为什么函证值得做成系统。** 货币资金舞弊是近年 A 股财务造假的重灾区——康得新 122 亿元
"存款"、康美药业约 300 亿元货币资金造假，暴露的共同环节都是**函证过程失控**（回函被
拦截、伪造，或由被审计单位"代收转交"）。监管层因此自 2020 年起推动**银行函证集中处理与
电子函证**。本项目本质是一个微型电子函证工作台：状态可追溯、流程不可绕过、差异强制闭环。

**流程对齐《中国注册会计师审计准则第 1312 号——函证》：**
- 函证的发出与收回全程由**审计方**控制（本平台以事务所身份运行，函件由平台生成）；
- **积极式 vs 消极式**的选用条件（消极式仅限低风险、小额、同质、预期例外率低的总体）；
- **未回函的替代程序**：应收账款可查期后回款 / 发货单 / 合同；**银行存款原则上不可用替代
  程序替代**（平台对银行类函证显式提示这一点）；
- **回函差异的调查**——即下述三分法。

**回函差异 ≠ 错报，到手先做三分归因：**
1. **未达账项**（时间性差异）——如 12-31 银行已计息而企业未入账，编银行存款余额调节表即消化；
2. **记账错误**——需提出审计调整分录；
3. **舞弊迹象**——金额方向异常、回函印鉴/笔迹可疑、企业阻挠直接函证。
平台把差异单列一栏并强制归因，就是不让第 ③ 类混在"已回函"里溜走。

**两个内行细节：**
- 往来询证函必含「**本函仅为复核账目之用，并非催款结算依据**」——防止被询证方当催款函而拒回（平台模板已含）。
- **一份银行询证函覆盖该行全部事项**（存款+借款+担保+承兑…），按《银行函证及回函工作操作指引》
  标准格式分节列示；平台按"银行 + 被审计单位"聚合生成（演示：工行海河的函同时列存款与借款）。

**与银行内审岗的衔接：** 本平台"多线任务 + 状态留痕 + 例外强制闭环"的结构，与银行内审的
**问题整改台账（整改—销号/核销管理）**同构——把函证换成整改事项，它即是一个内审整改跟踪系统。
